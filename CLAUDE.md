# CLAUDE.md — IMS Rouwmaat Groep

Instructies en context voor Claude Code (en voor een opvolger of IT-partij). Houd dit bestand bij als er architectuur of keuzes veranderen.

## Wat is dit

Integraal managementsysteem (webapp) voor Rouwmaat Groep: ISO 9001, ISO 14001, CO2-prestatieladder, SCL, VCA**, BRL 2000/7000 (+ BRL's grondbank/granulaat), SVMS-007, SC-530/540. Volledige specificatie: `docs/specificatie.docx`. Huisstijl: `docs/huisstijl.pdf`.

Gebruikers: QHSE (beheer), middenkader (~40), directie. Overige medewerkers lezen documenten via SharePoint/Appy, niet via deze app. Interface is **Nederlands**.

## Stack

- **Next.js 15** (App Router, React 19, TypeScript strict), server components + server actions; geen aparte API-laag.
- **PostgreSQL 16** + **Prisma 6** (`prisma/schema.prisma`, migraties in `prisma/migrations`).
- **NextAuth v4** met Microsoft Entra ID (provider `azure-ad`), JWT-sessies.
- **Tailwind CSS 4**; huisstijl als CSS-variabelen (`src/app/globals.css`, `@theme`) en in `src/theme/brand.ts`.
- **zod 4** voor validatie van alle formulierinvoer.
- Tests: Node test runner via `tsx` (`npm test`, bestanden `*.test.ts` naast de code).

Versies zijn exact gepind in `package.json`. `overrides` pinnen postcss, effect en deepmerge-ts op versies zonder bekende kwetsbaarheden; controleer bij upgrades of ze nog nodig zijn.

## Architectuurkeuzes

1. **Flexibel normenkader.** `Norm` → `NormRequirement` (hiërarchisch via `parentId`). Bewijs (documenten, processen, processtappen, risico's, acties, auditbevindingen) wordt via many-to-many-relaties aan eisen gekoppeld; één bewijsstuk kan meerdere normen afdekken. Dekking per norm = aandeel 'blad'-eisen met ≥ 1 gekoppeld bewijs (`src/lib/coverage.ts`). Basis voor de latere normmatrix en audit-ready-score.
2. **Locatie en discipline** zijn stamgegevens en optionele kenmerken op acties, risico's, audits, enz. "Leeg" betekent bedrijfsbreed / alle locaties.
3. **Rechten komen uit Microsoft 365.** De rol (QHSE > DIRECTIE > MIDDENKADER) wordt bij elke login bepaald uit Entra ID-groepen (`roleFromGroups`; bij group overage via Graph `checkMemberGroups`) en in `User.role` gecachet. Geen groep = geen toegang. Wat een rol mag staat in `PERMISSIONS` in `src/lib/rbac.ts`. Acties: QHSE alles; anderen alleen eigen acties (eigenaar of aanmaker).
4. **SharePoint is de enige bron voor documenten.** `Document` bevat alleen verwijzing + gecachete metadata. Sync en preview via Graph met het **gedelegeerde token van de gebruiker** (dus met diens SharePoint-rechten). Het token zit versleuteld in de NextAuth-JWT-cookie en verlaat de server niet. Handmatige registratie (link) is mogelijk zolang Graph nog niet is gekoppeld.
5. **Audit trail.** Elke mutatie (CREATE/UPDATE/DELETE/SYNC), elke login en het bekijken van detailpagina's (VIEW) wordt gelogd in `AuditLog`. Nieuwe server-acties en detailpagina's moeten `logAudit` aanroepen.
6. **Server actions-patroon.** Elke actie: `return safeAction(async () => { const user = await requirePermission(...); const data = parseForm(schema, formData); …; await logAudit(...); revalidatePath(...); })`. Gebruikersfouten gooi je als `UserError` (tekst in het Nederlands); die verschijnen boven het formulier. Formulieren gebruiken `<Form action={...}>` uit `src/components/form.tsx`, nooit een kale `<form action>`.
   6a. **Rechten op pagina's**: pagina's gebruiken `requirePagePermission` (stuurt door naar `/geen-toegang`), server-acties `requirePermission` (gooit `UserError`). Nooit `requirePermission` in een pagina: dat geeft een foutpagina (500).
   6b. **Lange lijsten**: `paginate` (`src/lib/paging.ts`, 100 per pagina, `?pagina=alle`) + `Pager` uit `ui.tsx` (milieuaspecten). Formulieren per tabelregel niet allemaal meesturen maar alleen voor de gekozen regel (`?wijzig=<id>`, zie auditvragen): elke regel met een keuzelijst van alle wettelijke eisen maakte die pagina 1,7 MB.
   6c. **Telefoon** (< 1024 px menu, < 768 px telefoon): het menu is een lade achter ☰ in een kopbalk (`Sidebar`, sluit bij navigeren en Escape); tabbladen (klasse `tabs`) één rij om te vegen; `table.table` scrolt zelf horizontaal; rasterkolommen `min-width: 0`; invoer 16 px (geen iOS-zoom); filterformulieren in `<Filters>` (`src/components/mobile-filters.tsx`) achter de knop "Filters (n actief)". Tegelrijen `grid-cols-2` op de telefoon. Nieuwe pagina's: tabbladen met `tabs`, filters in `<Filters>`.
7. **Inlogmodus** (`AUTH_MODE`, `src/lib/env.ts`). **"password" (online, tijdelijk):** één beheerder uit `ADMIN_EMAIL`/`ADMIN_PASSWORD` (min. 12 tekens, vergelijking in constante tijd, `src/lib/password-login.ts`), NextAuth Credentials, rol QHSE; slot na 10 mislukte pogingen in 15 minuten (geteld via `AuditLog` met entityType `LoginAttempt`, werkt serverless). Seed maakt in deze modus geen test-/lokale gebruikers. **"local" (fase 1, nu):** geen inlogscherm; `requireUser()` geeft de lokale gebruiker (`LOCAL_USER_NAME`, e-mail `lokaal@ims.local`, rol QHSE) of de via **"Bekijken als"** gekozen gebruiker (cookie `ims_bekijk_als`, server-actie `setViewAs`). De middleware (Node.js-runtime, leest `.env` tijdens het draaien) weigert in deze modus elk verzoek waarvan de host niet `localhost`/`127.0.0.1`/`::1` is, en `npm run dev`/`start:local` binden op 127.0.0.1. **"entra" (fase 2):** NextAuth met Microsoft Entra ID, rol uit Entra-groepen. Zonder `AUTH_MODE`: "entra" als de AZURE_AD_*-gegevens zijn ingevuld, anders "local". De seed maakt in de lokale modus de lokale gebruiker en testgebruikers `test.*@ims.local`. De rol heette eerder KAM; die heet nu **QHSE** (migratie `rename_kam_to_qhse`).
8. **Huisstijl centraal.** Kleuren in `brand.ts` én `globals.css` (`brand.test.ts` bewaakt dat ze gelijk blijven). Gebruik Tailwind-klassen `bg-brand-red`, `text-brand-red-dark`, `bg-brand-grey-light`, enz. Lettertype Fira Sans via `@fontsource` (werkt offline). Dezelfde `brand.ts` wordt later gebruikt voor de PowerPoint-directiebeoordeling en Teams/Outlook-meldingen.

9. **Risico's en kansen** (`src/app/(app)/risicos`). Methode volgens het register van Rouwmaat: score = kans × effect (1–25), niveaus **laag 1–7 / midden 8–14 / hoog 15–25** (`riskLevel`, `src/lib/risk.ts`, met de aanpak per niveau in `RISK_LEVEL_APPROACH`). Prioriteit (`riskPriority`): **★ 1 strategisch** (vinkje `strategic`, uit de contextanalyse), 2 = hoog niveau, 3 = regulier. Risico's op een groen-geel-rode schaal, kansen op een groene schaal. _Restrisico_ = beoordeling na maatregelen, of de bruto score zolang die ontbreekt (`residual()`); "na" vereist kans én effect. Code: het nummer uit het eigen register (`externalRef`, bijv. R01/K12) via `riskDisplayCode`, anders `R-001` / `K-001`. Velden uit het register: herkomst, contextfactor, thema, BU's (many-to-many met `Discipline`; leeg = groep), eigenaar als tekst (`ownerText`, rollen zoals "QHSE") naast een optionele gebruiker, termijn, aanpakstatus (`TreatmentStatus`), monitoring/KPI, kader, laatst beoordeeld (volgende beoordeling = +12 maanden), opmerking. Categorie `SAFETY` = arbo/RI&E. Rechten: QHSE alles; middenkader maakt aan en wijzigt eigen risico's (eigenaar/aanmaker); directie leest. Maatregelen worden acties met bron `RISK` en `riskId`. Filters staan in `src/lib/risk-filters.ts` en worden gedeeld met de CSV-export (`/risicos/export`, kolommen als in het register; Excel-NL: puntkomma, BOM, formule-injectie geneutraliseerd). Matrixcel-, klasse- en prioriteit-2/3-filters werken op berekende waarden en worden in code toegepast (niet in SQL). Import (`/risicos/import`, `src/lib/risk-import.ts`): tabbladen Risico's en Kansen één voor één; soort uit het nummer (K… = kans), bijwerken op nummer, anders omschrijving + soort; BU's op naam (komma's, "Groep" = bedrijfsbreed).
10. **Formulieren** verzenden via `onSubmit` + transition (zie `src/components/form.tsx`), níet via de `action`-prop: React 19 wist anders het formulier ook bij een foutmelding. Alleen 'toevoegen'-formulieren die op de pagina blijven krijgen `resetOnSuccess`. **Wijzigformulieren krijgen een `key` op de gegevensversie** (bijv. `key={entity.updatedAt.toISOString()}`): ongecontroleerde velden nemen nieuwe `defaultValue`s niet over, dus zonder key tonen ze na een wijziging elders (statusknop, andere actie) verouderde waarden en kan opslaan die terugzetten.
11. **Audits** (`src/app/(app)/audits`). Codes `AU-001`, bevindingen `AU-001/2` (volgnummer per audit, `src/lib/audit-plan.ts`). Checklist = `AuditChecklistItem` per normeis (alleen eisen van de normen van de audit; bij het verwijderen van een norm uit de scope vervallen de regels). Een bevinding op een eis zet de checklistregel op `FINDING`. Afhandelen van een bevinding kan pas als alle acties gereed/vervallen zijn, en bij major/minor pas na vastleggen van de oorzaakanalyse. Acties vanuit een bevinding krijgen bron `AUDIT`, `findingId` en de normeis. Cyclusplanning (`/audits/cyclus`): per blad-eis per kalenderjaar 'getoetst' (afgeronde audit met resultaat ≠ niet getoetst), 'gepland' of niet afgedekt; geannuleerde audits tellen niet mee. Rechten: QHSE beheert audits en bevindingen; iedereen leest; acties aanmaken volgens `actions.create`.
12. **Sorteren van eisen**: `compareRequirement` alleen voor eisen op hetzelfde niveau (boom, `flattenTree`); voor platte lijsten over niveaus heen (keuzelijsten, checklists) `compareRequirementFlat` (op paragraafnummer).
13. **Wet- en regelgeving** (`src/app/(app)/wetgeving`). `LegalRequirement` (code `W-001`) met compliancestatus; de status verandert alleen via een **toetsing** (`ComplianceAssessment`, historie = bewijs voor ISO 14001 9.1.2). Alleen de meest recente toetsing bepaalt de actuele status; volgende toetsing = datum + `reviewIntervalMonths` (`addMonths`, `src/lib/compliance.ts`). Bij 'voldoet niet' is een actie verplicht (tenzij er al een open actie loopt); acties krijgen bron `COMPLIANCE` en `legalRequirementId`. Compliancegraad = voldoet / (alle statussen behalve n.v.t.). Wettelijke eisen tellen als bewijs in de normdekking. Rechten: QHSE beheert en importeert; de eigenaar (middenkader) mag toetsen; directie leest. Filters in `src/lib/legal-filters.ts` (combineren via `AND`, gedeeld met export). Velden uit het register van Rouwmaat: nummer (`externalRef`, W001, getoond via `legalDisplayCode`), thema, soort regelgeving, van toepassing (`Applicability`; "Nee" grijs in de lijst), geldt voor (many-to-many `norms`: ISO 14001, CO2-prestatieladder, VCA**, ISO 9001 uit de vinkjeskolommen), bewijslast, eigenaar als tekst (`ownerText`), uitvoeringsstatus (`ImplementationStatus`, los van de compliancebeoordeling), volgende stap, impact, herkomst en gekoppelde risico's (kolom "Risicoregister", op nummer; importeer daarom eerst het risicoregister).
14. **Compliance-audit per vestiging** (`src/app/(app)/wetgeving/vestigingen`, logica `src/lib/location-audit.ts`). Vragenbank `ComplianceQuestion` (auditvraag, bewijs om te bekijken, thema, optioneel gekoppelde wettelijke eis, volgorde, actief). Een `LocationAudit` (code `CA-001`) per vestiging en datum krijgt bij aanmaken de actieve vragen als `LocationAuditAnswer`; vraagtekst, bewijs, thema en eis worden **overgenomen** (blijft bewijs als de vragenbank later wijzigt; "Nieuwe vragen toevoegen" vult aan). Oordeel = `ComplianceStatus`. Score = voldoet / (beoordeeld − n.v.t.), groen ≥ 90%, geel ≥ 70% (`locationAuditScore`, `scoreBand`). Afronden kan pas als alles beoordeeld is en elke 'voldoet niet' een actie heeft (`completionProblems`). Acties krijgen bron `LOCATION_AUDIT`, `locationAuditAnswerId`, de eis en de vestiging. Rechten: QHSE beheert vragen en audits; de aangewezen auditor (gebruiker, ook middenkader) mag invullen, acties aanmaken, starten en afronden (`canFillLocationAudit`); heropenen/annuleren alleen QHSE. Het oordeel per vestiging verandert de compliancestatus van de eis **niet** automatisch; de detailpagina van de eis toont het laatste oordeel per vestiging als input voor de toetsing. Import van het tabblad Compliance-audit: vragen uniek op nr. eis + vraagtekst (`questionKey`); ingevulde oordelen/bevindingen/acties worden een audit per vestiging + datum audit. Export in dezelfde kolommen (laatste audit per vestiging; acties als "#12 …", die worden bij herimport niet opnieuw aangemaakt).

15. **Excel-import** (algemeen: `src/components/import-wizard.tsx` + `src/lib/spreadsheet-import.ts`; per module een veldenlijst, bijv. `LEGAL_IMPORT_FIELDS`, `ASPECT_IMPORT_FIELDS`, en een server-actie die `ImportRow[]` opnieuw valideert). Eerst gebouwd voor `/wetgeving/import`. Het bestand wordt **in de browser** gelezen (`read-excel-file/browser`, of de eigen CSV-parser); alleen de gekoppelde kolommen gaan als JSON naar de server-actie `importLegal` (limiet 5 MB, `next.config.ts`), die alles opnieuw valideert. Pure importfuncties in `src/lib/legal-import.ts` (kolommen voorstellen, kopregel vinden, status/categorie/datum herkennen; getest). Bijwerken op kenmerk, anders op wet + artikel; lege cellen wissen niets; disciplines/locaties/eigenaren op naam (eigenaar ook op e-mail). Een status uit de import wordt als toetsing vastgelegd ("Overgenomen uit import"). De CSV-export gebruikt kolommen die direct weer te importeren zijn. **Niet** het npm-pakket `xlsx` gebruiken (verouderd, bekende kwetsbaarheden). De kopregel wordt gevonden als eerste regel met (bijna) evenveel tekstcellen als de breedste regel bovenin (`findHeaderRow`), zodat titel- en groepskoppen erboven worden overgeslagen. Vestigingen (`/beheer/vestigingen-import`, tabblad Vestigingen uit het register wet- en regelgeving): naam, adres, plaats, activiteiten, energiebesparingsplicht. **Volgorde bij een eerste vulling:** vestigingen → risico's → kansen → wet- en regelgeving → auditvragen (compliance-audit) → milieuaspecten (MAR).
16. **Milieuaspecten** (`src/app/(app)/milieuaspecten`, logica `src/lib/aspects.ts`, tellingen `src/lib/aspect-stats.ts`). Methode volgens het milieuaspectenregister (MAR) van Rouwmaat. **Risico = effect (E) × voorkomen (B) × waarschijnlijkheid (W)** (Fine & Kinney; schalen `EFFECT_SCALE` 1/3/7/15/40, `EXPOSURE_SCALE` 0,5–10, `PROBABILITY_SCALE` 0,1–10; opgeslagen als Decimal, risico altijd live berekend). Niveau ≤ 20 laag, 21–70 middel, 71–200 hoog, > 200 zeer hoog (`aspectRiskLevel`). **Prio H/M/L** is de eigen weging (risico, levenscyclus, wetgeving, stakeholders); **prio H of M = significant** (`isSignificant`, bij opslaan in `significant` gezet voor filteren). **Signaal** (`prioritySignal`): prio wijkt af van het risiconiveau (hoog en zeer hoog tellen als H; kansen tellen niet mee) → onderbouwing prio vastleggen. Velden uit het MAR: nummer (`externalRef`, A001, getoond via `aspectDisplayCode`), bedrijfsonderdeel en locatie als tekst (`businessUnit`, `locationText`; koppeling aan discipline/vestiging alleen als de naam overeenkomt, met aliassen "Afval & Recycling"/"Transport" → Afval/Transport), type (vestiging/project/groep), status locatie (`inOperation`: tijdelijk niet in werking telt niet mee in de tellingen), MBA (Bal), milieuthema (→ `aspectType`; Calamiteiten → noodsituatie), contextfactor, wettelijke eis + omschrijving, stakeholders, klachten, voorzieningen, kans/bedreiging, levenscyclus per fase (1–3, leeg = n.v.t.) met bron, maatregel, eigenaar (functie), herkomst. Overzicht (`/milieuaspecten/overzicht`) telt zoals het overzichtsblad van het MAR (per bedrijfsonderdeel, locatie, contextfactor en thema). Import van tabblad MAR: kolommen herkend op de kopteksten van het MAR; "Register nr." → wettelijke eisen (W-nummers), "Risico- en kansenregister" → risico's/kansen (R/K-nummers); bijwerken op nummer, anders bedrijfsonderdeel + locatie + activiteit + aspect; lege cellen wissen niets. De eerdere F × E × O-methode met instelbare drempel is vervallen (migratie `aspects_mar`: bestaande significante aspecten → prio middel, overige → laag). Gekoppelde aspectlijsten elders (`AspectLinkItems`) tonen er maximaal 12 met een link naar het gefilterde register (`?wet=`, `?risico=`, `?proces=`). Acties krijgen bron `ENVIRONMENTAL_ASPECT`. Aspecten tellen mee als bewijs in de normdekking. `co2Relevant` (standaard bij thema energie/CO2 of contextfactor energie) markeert aspecten voor de CO2-module. Rechten: QHSE beheert; iedereen leest; acties volgens `actions.create`.
17. **Context en stakeholders** (`src/app/(app)/context`, parser `src/lib/context-import.ts`, gegevens `src/lib/context-data.ts`). De **context- en stakeholderanalyse** (Word) is het uitgangspunt: inlezen via `/context/versies` (server-actie, limiet 25 MB in `next.config.ts`) met `mammoth` → HTML, opgedeeld in delen ("DEEL n"-tabel) en paragrafen (Kop 2 "3.1 …", Kop 1 = samenvatting) → `ContextAnalysis` / `ContextSection` / `ContextImage` (afbeeldingen in de database, geserveerd via `/context/afbeelding/[uuid]`, alleen ingelogd). HTML wordt **opgeschoond met `sanitizeContextHtml`** (allowlist; afbeeldingen alleen van de eigen route) bij inlezen, bij opslaan én bij tonen. Versies: CONCEPT → APPROVED (vaststellen: recht `context.approve`, directie of QHSE; vorige → SUPERSEDED; herbeoordeling +12 maanden, melding op het dashboard). Een **vastgestelde versie is niet bewerkbaar** (bewijs): "Wijzigen" maakt een conceptkopie (`createDraftFromAnalysis`, afbeeldingen gekopieerd met nieuwe ids), waarin QHSE paragrafen bewerkt (`RichTextEditor`, contentEditable zonder extra bibliotheek), toevoegt of verwijdert en afbeeldingen uploadt. "Afdrukken / PDF" via de browser (print-stijlen verbergen menu en knoppen); het Word-bestand in SharePoint wordt niet automatisch bijgewerkt. Uit dezelfde upload: **contextfactoren** (tabel "Contextfactor | Belang | Karakter | Wat we ermee willen"; extern/intern en paragraaf via `matchFactorSection` op deel 3/4), **stakeholders** (§5.1) en **verplichtingen** (§5.2, wettelijk/contractueel/vrijwillig, gekoppeld aan stakeholders via `matchObligationStakeholders` en handmatig aan wettelijke eisen); bijwerken op naam, niets wordt verwijderd. Contextfactoren koppelen **op naam** aan risico's en milieuaspecten (veld `contextFactor`); hernoemen werkt door in beide registers; onbekende namen in de registers worden gemeld. Rechten: `context.edit` = QHSE; iedereen leest.
18. **Meldingen en actielijst** (`src/app/(app)/meldingen`, `src/app/(app)/acties`; logica `src/lib/reports.ts`, `src/lib/action-filters.ts`, `src/lib/action-origin.ts`). `Report` (code `M-001`, of eigen nummer `externalRef`) voor afwijkingen/NC's, klachten, ongevallen, bijna-ongevallen, onveilige situaties, milieu-incidenten, schade en verbetervoorstellen (`ReportType`), met herkomst, ernst, letsel/verzuimdagen/meldplicht, directe maatregel, oorzaakanalyse (methode, categorie), faalkosten, behandelaar, effectiviteit en normeisen. **Melden mag iedereen** (`reports.create`); wijzigen: QHSE, melder of behandelaar zolang open (`canEditReport`); status en afsluiten alleen QHSE (`reports.manage`). **Afsluiten** pas als alle acties gereed/vervallen zijn en — behalve bij verbetervoorstel/overig — oorzaak én effectiviteit zijn vastgelegd (`reportCloseProblems`); afwijzen vereist een toelichting. Het overzicht is **gescheiden per groep** (`REPORT_GROUPS`, tab `?groep=`): ongevallen en incidenten / klachten / afwijkingen (NC) / verbetervoorstellen en overig. **Auditbevindingen horen niet bij meldingen**: die staan bij de audits en, voor de opvolging, in de actielijst (tab `/acties?tab=audit`, `FindingOverview`) — elk met eigen tegels, grafieken, filters en export; ook het dashboard en de directiebeoordeling houden ongevallen, klachten en afwijkingen apart. Bij ongevallen: **categorie** (`accidentCategory`, lijst `ACCIDENT_CATEGORIES`) en **verzuimklasse** (`absence`: vinkjes 'letsel/verzuim 1–15 dagen' en 'meer dan 15 dagen'; gecontroleerd tegen de verzuimdagen in `absenceFromInput`) en vinkjes **meldplichtig** en **fataal** (fataal = letsel dodelijk en altijd meldplichtig; filters `?meldplichtig=ja`, `?fataal=ja`). Acties vanuit een melding krijgen `reportId` en bron volgens `actionSourceForReport` (INCIDENT / NONCONFORMITY / COMPLAINT / OTHER). **Actielijst**: alle acties uit alle bronnen; `kind` (taak, directe correctie, corrigerende maatregel, verbetering), eigenaar als gebruiker of tekst (`ownerText`), controle op effectiviteit (`verifiedAt`, `verificationNote`), herkomst als code + link (`actionOrigin`). Filters gedeeld met de CSV-export. Import van actielijst (`ACTION_IMPORT_FIELDS`; "#12" uit de eigen export wordt herkend als actie 12) en meldingenregister (`REPORT_IMPORT_FIELDS`); bijwerken op eigen nummer; soort/status/bron/ernst/letsel herkend uit tekst.
19. **Grafieken** (`src/components/charts.tsx`): `BarList` (lichtgrijs spoor, optioneel `color` per regel, bijv. `progressColor` voor dekking: groen ≥ 80 %, oranje ≥ 50 %, anders rood, zoals `ProgressBar`), `Columns` (per maand, max. 3 gestapelde reeksen, totaal boven de kolom; as met `niceStep` en Nederlandse getallen via `compact`, tekst 11 px), `SegmentBar` (legenda in tekstkleur, ook als link), `ChartCard`.
